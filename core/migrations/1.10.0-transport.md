## 2. API

共通：`模型.create(參數) → { root, params, …子物件, set? }`。`meta.params` 是目錄頁可調的數值，`meta.options` 是程式才傳的選項；子物件選項給 `false` 不裝、沒給的欄位用預設；外部材質原樣使用。
線型輸送設備沿本地 +X、原點在中心線地面；`span: [起, 迄]` 指定本體的本地 X 範圍（預設以原點為中心的 `length`）——**站內沿用絕對座標時 root 只移到中心線（Z），不沿 X 位移**，子物件的本地 X 就是站的座標（逐位元相同）。
位置清單可給陣列或 `{ from, to, pitch, closed }`（`for (x = from; closed ? x <= to : x < to; x += pitch)`，和站內原本的迴圈同一種累加）。

### beltConveyor（平皮帶輸送機）
- params：`length` 1600、`width` 300、`top` 700（承載面高度）、`rollerR` 42；state：`s`（輸送距離 mm）。
- options：`span`；`carry { t=14, material, color, name }`；`texturePitch=100`；`back { t=10, y, material=MAT.belt }`；`bed { size=[長−20,16,寬−30], y=top−t−18, material=MAT.steel }`；`rollers { r, length=寬+14, y=top−r−8, x=[起,迄], segments=20, material=MAT.roller }`；`sides`（陣列，每項左右各一：`{ h, t, y, z, length, x, material }`；預設側樑 90×20＋擋邊 50×10）；`legs { x, z=[0], size=[60, top−100, 60], material=MAT.frame, foot=140 }`。
- 回傳：`carry`、`back`、`bed`、`rollers[]`、`sides[]`、`legs[]`、`set({ s })`（`carry.material.map.offset.x = −s/texturePitch`；`roller.rotation.y = s/半徑`）。
- **界定**：模型＝皮帶機本體（承載面、回程面、滑床板、頭尾滾筒）＋選配的標準機身（`sides` 側樑／擋邊、`legs` 支腳＋腳座）。現場既有的機架與鏽色側牆、導料板、馬達與吊架、編碼器、感測器留在站內。

### edgeBeltConveyor（邊皮帶雙軌輸送段）
- params：`length` 1200、`width` 200（兩軌內側面間距）、`top` 900；state：`s`。
- options（每一側 −Z 先、+Z 後）：`rail { h=50, w=20, y=top+12−h/2, z=width/2+w/2, material=MAT.alu }`；`belt { h=2, w=8, inset=15, y=top−h/2, z=width/2−w/2, material=綠 }`；`lip { h=3, w=6, y, z, material }`；`fasteners { type:'screw'|'bolt', x, y, r, material, socketMaterial }`；`strip`（預設不裝；`{ size, x, y, z, material }`）；`pulleys { r=14, w=10, x, y=top−15, z, segments=20, material }`；`legs { x, size=[40, top−38, 40], y, z, material, name, foot: false | { size=[90,10,70], y, material, name } }`（預設名稱 `conveyor leg`／`conveyor foot`）；`cross { x, size=[30,30,width+40], y=top−60 }`；`drive { size, pos, material=MAT.steelBlue }`；`adjust`（預設不裝；`{ x, rod {…}, servo {…} }`）；`marks { size=[3,.6,7], x, y=top+.3, z, material, pitch }`。
- 回傳：`rails[2]`、`belts[2]`、`lips[]`、`strips[]`、`pulleys[]`、`legs[]`、`feet[]`、`fasteners[]`、`cross[]`、`drive`、`adjust { rods, servos }`、`marks`（刻線群組）、`set({ s })`（`marks.position.x = ((s % pitch) + pitch) % pitch`）。

### conveyor（滾筒輸送線，擴充的選項）
- `axis: 'x'|'z'`、`span`、`rollers { from, to（給了就是 < to）, pitch, skip=[[中心, 半寬]], y, segments, material }`、`brackets`（預設不裝；`{ size=[軸向, 高, 輸送向]=[26,68,70], offset=width/2+7, y=height−roller−6, material=MAT.steelDark }`）、`frame { h=150, w=50, y, offset=width/2+25, material=MAT.steel }`、`legs { positions, size, offset, material=MAT.steelDark, foot=120|false }`、`name`。
- 回傳多了 `rollers[]`、`positions[]`、`brackets[]`、`frames[]`、`legs[]`；`set({ s })` 在 `axis:'z'` 時轉 `rotation.x`。

### vRollerConveyor（V 槽滾輪輸送線）
- params：`length` 2600、`axisY` 440、`pitch` 330、`vee` 25°、`waist` 40、`halfL` 260；state：`s`。
- options：`span`；`rollers { from=起+200, to=迄−170, closed=true, pitch, skip, segments=28, material=MAT.roller, contactR=100 }`；`stubs { r=12, length=60, offset=halfL+30, segments=8 }`；`frame { h=140, w=50, y=axisY, offset=halfL+60, material=MAT.steel }`；`legs { positions={ from: 起+100, to: 迄, pitch: 1150, closed }, size=[70, axisY−70, 70], offset, material=MAT.steelDark }`。
- 回傳：`rollers[]`（共用一份 LatheGeometry；自轉用 `rotation.y`）、`positions[]`、`stubs[]`、`frames[]`、`legs[]`、`set({ s })`。

### stopper（止擋）
- params：`stroke` 24；state：`up`（1 升起、0 降下）。原點＝止擋件中心線、輸送面高度。
- options：`pin { r=6, h=26, y=−1, segments=16, material=MAT.chrome }`；`blade { size=[10,24,68], y, material=MAT.yellow }`（給了就取代圓銷）；`body: false | { size=[30,40,30], pos=[6,−40,0], material=MAT.black }`；`up`（建立時的狀態，預設 1）；`partName`。
- 回傳：`body`、`slide`（升降群組）、`part`（止擋件網格）、`set(v 或 { up })`：`slide.position.y = (v − 1) × stroke`。

### ballTurntable（萬向球旋轉台）
- params：`top` 500（球頂）、`radius` 330、`pitch` 90、`ballR` 24；state：`angle`（度）。
- options：`grid { span=radius−60, limit=radius−30 }`、`disc`、`cup`、`ball`、`base: false | { r=180, h=90, y=top−145 }`、`drive: false | { pos=[225,180,0], scale=.65, yaw }`。
- 回傳：`table`（轉盤群組）、`disc`、`cups[]`、`balls[]`、`base`、`drive`、`set({ angle })`（`table.rotation.y = angle × D2R`）。

### flexFeeder（柔性供料盤）
- params：`w` 150、`d` 110、`top` 115、`baseY` 5（預設是落地單機；機身由 `baseY−5` 到 `top−5`）。options：`margin=40`、`bodyMaterial=MAT.black`、`plateMaterial`、`plateT=4`、`hopper: false | { size=[80,60,60], pos=[w/2+60, top+10, 0], material=MAT.alu }`。回傳 `body`、`plate`、`hopper`。

### pallet／shuttleCar／shuttleRack／jibCrane／dolly／agvCharger
- `pallet.create({ size=1200, height=150, deck=30, runner=100, runnerX, material, empty })` → `deck`、`runners[]`；`pallet.instances([[x,y,z]…], 參數)` → `{ root, meshes[4 個 InstancedMesh] }`。root 名稱 `pallet`。
- `shuttleCar.create({ width=1000, length=1080, height=120, …Material })` → `body`、`wheels[]`、`deck`、`lamps[]`；原點在軌道頂面。
- `shuttleRack.create({ pitch, zFront, topBeam, lanes, levels, zBack, fronts, blocks, frameZ, brace, railX, guideX, labels })` → `lanes`、`posts[]`、`rails[]`、`front(i)`。
- `jibCrane.create({ armY=3000, reach=1550, gripR=282.5, gripOpen=60, mastR=130 })` → `mast`、`arm`、`trolley`、`chain`、`clamp`、`claws[]`、`set({ a 度, r, y 夾具原點離地高度, grip })`。
- `dolly.create({ size=640, height=120, handle=950, …Material })` → `deck`、`wheels[]`；root 名稱 `dolly`（推著走＝移動 root）。
- `agvCharger.create({ w=400, h=1400, d=150, material, lampMaterial, lamp })` → `body`、`lamp`；正面朝 +Z。

## 4. 做不到完全相同、不換用、要注意的

**(A) 模型多一層 root 群組對 `scene` 檢查的影響（core 1.10.0 已處理）**
`core/verify/scene.mjs` 的 `mountedOn(A, m)` 原本用「移動件的父群組」判斷安裝關係。會動的子件進了模型 root 之後，它和 root 外面、同一個站群組裡的固定件就不再自動放行。
改之前用暫存腳本模擬（不改站：建好場景後把那些零件搬進放在原點的中介群組，再跑 `verifyScene`）：
- PCB（刻線群組＋止擋 ×3）、SSD（止擋＋刻線群組 ×3）、MGPC（止擋 ×5＋刻線群組）：結果與基準相同（0 筆，零件／會動／關節數相同）。
- 化學桶：懸臂吊、立放滾筒都相同；**旋轉台多出 4 筆 DYN**——轉盤邊緣的球座／萬向球與「桶蓋收集桶」（`line.js` 200-202，中心 X 11780）重疊（檢查量到 −37～−45 mm）。這是站內原本就有的重疊，之前被「同一群組＝安裝關係」蓋掉。

使用者的決定是「換用模型不能改變各站的檢查結果，被蓋住的既有問題另外記待辦」，所以 core 1.10.0 採用下面的改法（同一個模擬驗過，化學桶回到 0 筆）：

```js
// core/verify/scene.mjs：共用模型的根群組只是包裝，模型裡的移動件視為裝在「模型所在的那一台設備」上
const hostOf = A => { let p = A.parent; while (p && p.userData.coreModel && p.parent && p.parent !== scene) p = p.parent; return p; };
const mountedOn = (A, m) => bodyOf(m) === parentBody(A) && inside(m, hostOf(A));
const sameMount = (A, B) => parentBody(A) === parentBody(B) && (parentBody(A) !== null || hostOf(A) === hostOf(B));
```

- 規則：判斷「移動件裝在誰身上」時，從移動件的父群組往上跳過所有標了 `coreModel` 的 root（直接掛在 scene 底下的 root 不跳，它自己就是一台設備）。伸縮件的「同一載體」（`sameMount`）用同一個規則。
- 場景裡沒有 `coreModel` 標記時 `hostOf(A)` 就是 `A.parent`，判定和原本完全相同。
- 所以旋轉台的 `tt.table` 留在模型 root 裡即可，不必掛回 `line` 群組。
- **桶蓋收集桶與旋轉台重疊 37～45 mm 是真問題**（被安裝關係蓋住的既有狀況），要另外處理；請主 session 記進 `PENDING.md`（化學桶站）。

**(B) 不換用的**
- 化學桶「標籤旋轉輥」（兩支主動輥＋底座，`line.js` 67-71）：`verify-detail.mjs` 直接用 `rotRollers` 的本地座標對 `LYING.y／z`，而且是貼標站專用機構，只有 3 個網格；留站內。
- RS 主皮帶的側樑、鏽色側牆、支腳與橫撐、既有驅動馬達、編碼器、導料板與托架；分流帶的馬達與吊架（`electrical.js`）。
- 化學桶橫躺線的黃色側板、馬達、光電；立放線的黃色護欄、定位擋塊、頂升秤台、站名牌。
- MGPC 支腳裡的調整腳螺桿（232 行）、SSD 各段的站名貼紙、PCB 的頂升真空台。

**(C) 數值上的小差異**
- 腳座螺栓（`foot()` 的 InstancedMesh）：實例矩陣是 float32，RS 分流帶／分類帶的 root 有 Z 位移時，合成後的位置和原本差 < 1e-5 mm（畫面看不出來）。其餘 3,500 多個網格的世界矩陣逐位元相同。
- 同一組零件在群組裡的建立順序可能和原本不同（例如 MGPC 的端輪排在橫撐前面），不影響畫面；`scene` 報告只有在有發現時才會列出零件。
- 換用後 `review/determinism.json` 的物件數會多（每個模型多 root 與子群組），屬於實質但無害的變化。
- 模型給網格加了名稱（`belt carry`、`conveyor rail`…），原本沒名稱；已確認不會撞到各站用名稱判斷的規則。

## 換用後的比對（四份對照共用）

每一站換用前後用 `core/tools/scene-dump.mjs` 比對場景，再跑檢查與截圖：

```powershell
node core/tools/scene-dump.mjs <專案> --out TEMP/<簡稱>-after.json                                   # 換用後傾印
node core/tools/scene-dump.mjs --diff "TEMP/b2-dump/<專案資料夾名>.json" TEMP/<簡稱>-after.json --ignore-names   # 和換用前比
node core/tools/check.mjs <專案> --quick                                                             # 數字要和換用前相同
node core/tools/shots.mjs <專案> --out TEMP/<簡稱>-shots --compare TEMP/shots-b2-base --port <p>     # 0 張超過門檻
```

- 換用前的傾印已經放在 `TEMP/b2-dump/<專案資料夾名>.json`（core 1.10.0、各站還沒換用第二批時產生；站的程式在那之後被別人改過就要重新產生）。
- 目標是「結論：完全相同」。它比的是每個零件的幾何、頂點、世界矩陣、材質屬性、陰影旗標、可見性、名稱與走線五金，外加燈光與虛擬相機，9 個時間點、所有情境；多一層 root、建立順序不同都不算差異。走線五金（線夾、夾腳）另外有一段統計，夾腳跑掉會列在那裡。
- `--ignore-names`：共用模型會給原本沒有名稱的網格預設名稱，這不算外觀差異；走線五金的名稱照比。
- 它不比的：群組階層與 `userData`（`fx`、`guide`、`on`、keepout…）、貼圖內容、時間點之間的動作——所以 `check.mjs`（干涉、配線、站內自有檢查）與截圖仍然要跑。
