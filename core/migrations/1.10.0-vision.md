# core 1.10.0 換用對照：相機與視覺（`core/models/vision.js`）

給各站代理換用時照著改。照第 3 節的參數換，外觀與檢查結果不變；走線、全場檢查與各批共通的注意事項見 `core/MIGRATION.md` 的 1.10.0 一段。

## 1. 檔案、export、模型 id、分類

| 檔案 | export | 模型 id | 分類 | 名稱 |
|---|---|---|---|---|
| `core/models/vision.js` | `visionCamera` | `vision-camera` | 視覺 | 工業相機（逐件設定：機身、鏡頭、環形光、閃光、虛擬相機） |
| 同上 | `codeReader` | `code-reader` | 視覺 | 固定式讀碼器（含讀碼光束） |
| 同上 | `laserProfiler` | `laser-profiler` | 視覺 | 3D 線雷射輪廓儀 |

- 三個都已登記在 `core/models/index.js`，目錄頁（`/core/catalog/`）可預覽；`models` 檢查通過。
- `core/models/camera.js` **沒有修改**（id `camera`：依感光元件與焦距決定外形與視角，RecycleSorter 在用）。新的 `vision-camera` 是「逐件設定」，兩者並存；目錄頁會有兩個相機。
- 三個模型的 root 都有 `root.userData.coreModel = meta.id`；實體網格都**直接掛在 root 底下**（螺絲是 `screw` 群組），走線（`cable()`）會把它們當線夾固定面，和換用前「直接是站群組的子網格」時相同。

## 2. API

共同慣例（三個模型都一樣）：

- `axis`：光軸方向 `'-y'`、`'+y'`、`'+z'`、`'-z'`。其他方向旋轉 root。
- `at`：零件中心在光軸上的座標，**朝被攝物為正**，從 root 原點量起。原點由使用者決定。
- 截面 `size: [a, b]`：a 沿 X；b 在 Y 軸相機沿 Z、在 Z 軸相機沿 Y。方塊尺寸＝Y 軸 `[a, length, b]`、Z 軸 `[a, b, length]`。
- 子物件選項：`false` 不裝；不給或 `true` 用預設；物件逐欄蓋過預設。
- 材質由外部傳入時原樣使用、不複製；`shadow` 可為布林或 `{ cast, receive }`。
- 圓柱在 Y 軸相機不旋轉、Z 軸相機 `rotation.x = π/2`；圓環（Torus）相反。和各站原寫法相同。

### visionCamera.create(params) → `{ root, params, body, lens, bands[], glass, ring, ringHousing, light, camera, screws[], label, parts[], set }`

| 參數 | 預設 | 說明 |
|---|---|---|
| `bodyW, bodyD, bodyL` | 44, 34, 47 | 機身截面與長度（meta.params） |
| `lensR, lensL` | 15, 36 | 鏡頭半徑與長度 |
| `ringR` | 34 | 環形光半徑，0 不裝 |
| `fov` | 20 | 虛擬相機垂直視角 |
| `axis` | `'-y'` | |
| `material` | `MAT.black` | 機身、鏡頭、環形光外殼的預設材質 |
| `body` | `{ size:[bodyW,bodyD], length:bodyL, at:−(lensL+bodyL/2) }` | 另有 `offset:[u,v]`、`bevel`（>0 用 `bevelBox`）、`material`、`shadow`、`name` |
| `lens` | `{ r:lensR, length:lensL, at:−lensL/2, segments:32 }` | `bore` >0 為套筒（ExtrudeGeometry 環形截面，遠心鏡筒用）；`material`、`shadow`、`name` |
| `bands` | 不畫 | `{ ats:[…], r, length（薄圓柱，segments 預設 40）或 tube（圓環，segments 預設 [6,40]）, material=MAT.alu, shadow, name }` |
| `glass` | `{ r:lensR×.7, length:1, at:.5, segments:32 }` | 預設材質深藍鍍膜（MeshPhysicalMaterial 0x203b50） |
| `ring` | `{ r:ringR, tube:5, at:0, segments:[8,36], on:1.4, off:.05 }` | 預設材質白色 emissive（每台一份）；`glow:false` 時 set 不改材質；`housing:{ r, bore, length, at, segments, material, shadow, name }` |
| `spot` | `{ color:0xffffff, distance:900, angle:.6, penumbra:.5, decay:1, at:0, target:500, power:600 }` | `type:'point'` 改用 PointLight |
| `view` | `{ fov, aspect:1.5, near:1, far:3000, at:玻璃前 .1 }` | `type:'orthographic'`＋`size:[寬,高]`；`up:[x,y,z]` 用 lookAt 矩陣定向（畫面上方＝up），不給時用歐拉角（−Y：`rotation.x=−π/2`、+Y：`+π/2`、+Z：`rotation.y=π`） |
| `screws` | 不畫 | `{ points:[[x,y,z]…], r=2, axis }`，root 座標 |
| `label` | 不畫 | `{ lines, w, h, pos, rot, options }`，`decal` 原樣傳入，root 座標 |
| `name` | `'vision-camera'` | root 名稱 |

- `set(v)`：v 是 0～1、布林或 `{ light }`。環形光 `emissiveIntensity`＝off～on，閃光燈 `intensity`＝亮度 × power。
- 子網格預設名稱：`camera body`、`lens barrel`、`lens band`、`lens glass`、`ring light`、`ring light housing`、`camera view`、`camera label`。

### codeReader.create(params) → `{ root, params, body, lens, light, camera, beam, fan, set, … }`

- meta.params：`w`=60、`h`=40、`length`=70、`beamW`=70、`beamL`=100。預設 `axis:'+z'`、原點在機身中心。
- `body`、`lens`、`spot`、`view` 的選項同相機（鏡頭、閃光、虛擬相機預設不裝）。
- `beam`（水平光帶，PlaneGeometry）：`{ w:beamW, length:beamL, at:length/2+beamL/2, drop:0, material }`；`fan`（扇形，三角形 BufferGeometry）：`{ apex:length/2, far:length/2+beamL−10, halfWidth:beamW/2+5, drop:−h/2, material }`；`beamMaterial` 是兩片共用的材質（預設紅色半透明雙面）。兩片都有 `userData.fx`，建立時隱藏。
- `set(v)`：布林、0～1 或 `{ scan }`。光束在 ≥0.5 時顯示；有閃光燈時 `intensity`＝亮度 × power。

### laserProfiler.create(params) → `{ root, params, body, window, plane, set }`

- meta.params：`w`=70、`h`=40、`length`=90、`fanW`=30、`range`=70。預設 `axis:'+z'`、原點在機身中心。
- `material`（機身，預設 `MAT.black`）、`shadow`、`window:{ size:[40,20], t:4, at:length/2+1, material, glow:[1.5,3] }`、`plane:{ w:fanW, length:range, at:length/2+range/2, material, opacity:.35, fx:true }`。
- `set(v)`：0～1、布林或 `{ laser }`。雷射面 `opacity`＝亮度 × .35，雷射窗 `emissiveIntensity`＝1.5～3。

## 3. 各站換用對照（照這些參數，逐網格比對相同）

### PCB-CopperAssembly `web/js/machine.js`

`camera()` 保留成包裝函式（簽名與回傳值不變，131／164／208／217 四處呼叫不用改），本體換成模型，兩條線材留在站內並加到 `c.root`：

```js
function camera(parent, pos, dir, { fov = 20, ringR = 34, power = 600, leadSide = 0 } = {}) {
  const s = dir === 'down' ? 1 : -1;
  const c = visionCamera.create({
    axis: dir === 'down' ? '-y' : '+y', material: matDark,
    body: { at: -60 }, lens: { segments: 20 },
    bands: { ats: [-7, -13, -25], r: 15.5, length: 1.4, material: matAlu },
    glass: { r: 11, length: .5, at: -1, segments: 40, material: new THREE.MeshPhysicalMaterial({ color: 0x203b50, metalness: .3, roughness: .09 }), shadow: { cast: false } },
    ringR, spot: { at: -s, power }, view: { fov, at: 0 },
  });
  const g = c.root; g.position.set(...pos); parent.add(g);
  // data、lightRoute 兩個陣列與兩行 cable(g, …) 原樣保留
  return { group: g, cam: c.camera, flash: c.set };
}
```

- `spot.at: -s`：原本的 SpotLight 沒設位置，three.js 預設在 `(0, 1, 0)`，朝下的相機是後方 1 mm、朝上的是前方 1 mm。
- `glow()` 可以刪（環形光預設材質的屬性相同）。`h.cam.group`、`upCams[H].group`、`.cam`、`.flash(bool)` 的用法都不變。

## 4. 不換用或不是完全相同的項目

- **WorkpieceMeasurement（相機、遠心鏡頭、線光源、背光、環形光）：不換用（已拍板；運動元件也一樣，見 motion 對照）。** 原因：
  1. `spec.js` 的 `fixedBodies()` 是不依賴 three 的純資料，`machine.js`、`collision.js`、`tools/verify*.mjs`、`wiring-plan.js` 共用同一份數字。core 模型依賴 three 與 `MAT`，要由模型輸出包絡就得讓 `spec.js` 反過來依賴 core，或在 core 裡收一份這一站自己的 `{ kind, min, max, p0, p1, r }` 格式。
  2. 每個元件只是一個圓柱或方塊，材質是本站的鍵名表加 `applyFinishes`，執行時還會整個換掉（`byId.lightG.material = …`）。換成模型省不到程式，只多一層轉換。
  3. 通道 A 的鏡頭與相機斜 60°，位置由 `along(DIR_A, r)` 直接算世界座標。改成「root 定位＋本地座標」後包絡要再乘一次矩陣，數值會有 1e-13 級的差，干涉檢查的間隙數字與 review JSON 不保證逐位相同。
  4. `camA` 的顯示是 33×33 方塊、碰撞是 r=22 圓柱，這種「顯示與包絡不同形」是本站的約定。
- **化學桶兩台相機的虛擬相機與閃光方向**：世界矩陣差 1.2e-16，不是逐位元相同（見上）。
- **軍規站工具上的三條線**：靠 core 1.10.0 的 `cable()` 認得模型 root 裡的網格，夾腳才會和換用前相同（見上）；換用後要比對。
- **預設名稱**：原本沒有名稱的網格，模型會給預設名稱（`camera body` 等）。站內的 verify／allow 規則若用「沒有名稱」判斷，要檢查一下。
- 各站支架、立柱、吊桿、線材、尾線、`UP-CAM` 貼紙留在站內，沒有進模型。
- **站自己加進相機 root 的東西**（SSD 的條形光、軍規讀碼器的立柱 `srStand`、快門相機的尾線、PCB 相機的兩條線）照舊加到 `cam.root`：root 就是原本那個群組，`cable(root, …)` 的固定面仍是 root 的直接子網格（加上條形光這類模型 root 裡的網格）。
- **和其他批次重疊的行號**：軍規 `cell.js` 193-195 同時有 S1 頂視相機（本檔）與 S1 Z 向滑台（motion 對照），兩邊都掛在 `head`，各換各的零件；SSD `cell.js` 的全局相機旁邊兩支條形光是 1.9.0 已換用的 `barLight`，照舊加到 `gcam`。

## 5. 驗證與結果

- **逐網格比對**：把各站原寫法複製到暫存腳本，和「模型＋上表參數」比對幾何型別與參數、頂點數與頂點座標、索引、世界矩陣、材質屬性（同一個材質物件或逐欄相同）、陰影旗標、`visible`、`userData`、名稱；光源比型別、顏色、強度、距離、角度、衰減、位置與方向；虛擬相機比型別、視角參數、`up`、投影矩陣、世界矩陣。**33 組全部相同**，世界矩陣最大差 2.84e-14（多一層 root 的浮點誤差；多數是 0）。
  - 涵蓋：PCB 5 種相機 × 熄／閃光／再熄（含兩條線材與線夾，共 21 個網格）、軍規手臂相機＋輪廓儀 × 3 種狀態、S1 頂視相機、S0 讀碼器、SSD 手腕相機（含條形光與線材，25 個網格）× 2、SSD 全局相機 × 2、化學桶 2 台、快門下視 × 2、上視 × 2、酸鹼讀碼器 × 3。

  - 另外用故意改錯的參數（分段數、位置差 0.001、陰影旗標、材質、角度、`up`、`fx`）確認腳本抓得到差異。
- **模型檢查**：三個模型的預設參數加上 `axis` 變化共 8 組，干涉 0、重合面 0；登記後 `node core/tools/check.mjs --only models` 通過，目錄頁用無頭瀏覽器逐一開過（拉動每個參數與狀態），沒有主控台錯誤。

## 換用後的比對（四份對照共用）

每一站換用前後用 `core/tools/scene-dump.mjs` 比對場景，再跑檢查與截圖：

```powershell
node core/tools/scene-dump.mjs <專案> --out TEMP/<簡稱>-after.json                                   # 換用後傾印
node core/tools/scene-dump.mjs --diff "TEMP/b2-dump/<專案資料夾名>.json" TEMP/<簡稱>-after.json --ignore-names   # 和換用前比
node core/tools/check.mjs <專案> --quick                                                             # 數字要和換用前相同
node core/tools/shots.mjs <專案> --out TEMP/<簡稱>-shots --compare TEMP/shots-b2-base --port <p>     # 0 張超過門檻
```

- 換用前的傾印已經放在 `TEMP/b2-dump/<專案資料夾名>.json`（core 1.10.0、各站還沒換用第二批時產生；站的程式在那之後被別人改過就要重新產生）。
- 目標是「結論：完全相同」。它比的是每個零件的幾何、頂點、世界矩陣、材質屬性、陰影旗標、可見性、名稱與走線五金，外加燈光與虛擬相機，9 個時間點、所有情境；多一層 root、建立順序不同都不算差異。走線五金（線夾、夾腳）另外有一段統計，夾腳跑掉會列在那裡。
- `--ignore-names`：共用模型會給原本沒有名稱的網格預設名稱，這不算外觀差異；走線五金的名稱照比。
- 它不比的：群組階層與 `userData`（`fx`、`guide`、`on`、keepout…）、貼圖內容、時間點之間的動作——所以 `check.mjs`（干涉、配線、站內自有檢查）與截圖仍然要跑。
