# core 1.10.0 換用對照：機器人與專用設備（`abb-irb360.js`、`equipment*.js`）

給各站代理換用時照著改。座標單位 mm。「原點」指模型 root 的原點；沒列的參數用預設值。
外部傳入的材質原樣使用（不複製）。每個模型的 root 都有 `root.userData.coreModel = meta.id`。
走線、全場檢查與各批共通的注意事項見 `core/MIGRATION.md` 的 1.10.0 一段。

模型的結構（和走線、全場檢查有關）：

- **整支會被站每格移動的 root**：`pipette-module`、`pipette-tip`（建立時在原點，之後跟著手臂走）、`spray-lance`（root 就是伸縮的那個群組）。這三個的 root 已標 `userData.cableHost = false`，`cable()` 不會拿它們當線夾固定面（換用前它們也是站裡的群組，本來就不算）。
- **root 不動、裡面有會動的子群組**：`abb-irb360`（主動臂、動平台、伸縮軸）、`analytical-balance`（`door`）、`autosampler`（`rack`、`head`、`prop`）、`labeler`（`pad`）、`upender`（`cradle`、`actuator`、`piston` 會改 scale）。`cable()` 只把 root 的直接子網格當固定面，這些子群組不算；全場檢查把它們視為裝在「root 所在的那個站群組」上（`scene.mjs` 的 `hostOf`），和換用前站裡的移動群組相同。
- `pe-tank` 的 `liquid`、`sight` 是 root 的直接子網格，會改 scale。
- `autosampler`、`titrator` 的 `meta.verify` 有 `skip`（印刷標示不是實體，和酸鹼站的 `isLabel` 相同）；`autosampler` 另有一條 `allow`（目錄的轉盤角度與滴定頭高度各自掃動，互鎖由站的排程保證）。拿掉這條，模型檢查會報 7 筆（探針、攪拌槳掃過杯座環）。
- `equipment-lab.js` 匯入 `equipment.js` 的 `liveScreen`。
- `safety-scanner` 的兩片區域多標了 `userData.fx = true`（原站靠 `verify.skip`）；這是唯一刻意和原站不同的標記，外觀不變。

## 2. API

### abb-irb360.js

- `createIRB360({ geometry = IRB360, name = 'irb360' })` → `{ root, platform, arms: [{ a, upper, rods: [{ rod, s }] }], outer, inner, set(p), state: { ok, theta, p }, geometry }`
  - 原點：三個肩關節所在水平面的中心。`set(p)`：`p = [x, y, z]`（動平台中心，root 座標；也接受 `{ x, y, z }`），到不了回傳 `false` 並保持上一個姿態。
  - 名稱照原樣：`delta arm 1～3`、`delta rod`、`delta ball`、`delta platform`、`delta telescope outer`／`inner`（`inner.userData.nested = outer`）。
- `deltaIK(p, G = IRB360)`、`IRB360 = { rb: 200, la: 520, lf: 1240, rp: 45, gap: 50 }`、`AZIMUTH`、`IRB360_MAT = { white, carbon, joint }`（工具共用）。
- 目錄用：`meta`（狀態 x ±350、y −1200～−900、z ±350）、`create(p)` → `{ root, platform, set({ x, y, z }) }`。
- **模型邊界**：本體＝上下殼、減速機座、主動臂、平行連桿、動平台、中央伸縮軸。吸嘴工具（`suction nozzle` 群組：轉接座、吸嘴筒、快拆環、波紋吸口 `suction cup`、真空產生器 `vacuum ejector`、`hose port`）與氣管（`air tube`，幾何每格重建）留在站內。
- 連桿尺寸仍是現場照片目測的示意值（接近動作範圍 1600 的機型），沒有用型錄核對過；檔頭註解有寫。

- `--ignore-names`：共用模型會給原本沒有名稱的網格預設名稱，這不算外觀差異；走線五金的名稱照比。

## 各站換用後的補充（2026-10-05，四份對照共用）

7 站照這四份換用時發現、上面各節沒寫到的事。之後的站換用時照這裡做。

- **原本是「站的普通群組」的設備換成模型**（相機、讀碼器、天平、進樣器、滴定儀、操作電腦、安全掃描器…）：root 有 `coreModel`，父群組上的 `cable(父群組, …)` 會把它的直接子網格當線夾固定面，換用前不會。線夾落在它 65 mm 內時走線五金會變多或改釘位置，要標 `模型.root.userData.cableHost = false`（酸鹼的分析天平、快門的下視相機），或保留原本那一層站內群組再把模型 root 放進去（快門的滑台）。先照文件換，傾印比對報走線五金不同再標。
- **`airCylinder` 用 `grow`**：桿端群組 `tip` 每格都在動，全場檢查把它算成關節。站原本掛在活塞桿上的零件（推板）改掛到 `tip`，`scene-verification.json` 的 `joints` 才和換用前相同；掛在 `rod` 上每支氣缸會多 1 個關節（軍規的推／拉料氣缸）。
- **`visionCamera` 的 `label`**：載入模型當下沒有 `document` 就不建立（`shapes.js` 的 `decal` 也是）。檢查腳本晚補 `document` 的站，標籤留在站內畫（SSD 的手腕相機）；已登記在 `core/REQUESTS.md`。
- **`visionCamera` 的 `view.name`、閃光燈的旋轉**：虛擬相機預設名稱是 `camera view`，閃光燈掛在 root 底下所以會跟著 root 的旋轉。`scene-dump.mjs --diff` 修正後這兩項都不算差異（燈光只比位置與目標點，`--ignore-names` 涵蓋燈光與相機），站內不用再傳 `name: ''`，也不用把燈轉回世界方向。修正前換用的站留著 `name: ''`，無妨。
- **原本有名稱的網格**：對照的程式片段有些只在註解寫「名稱照舊」。換用後要把名稱指定回去（例如軍規 `camBody.name = 'S1 頂視相機'`、`tcLens.name = 'S1 頂視鏡頭'`），站內用名稱判斷的 allow／verify／keepout 才不會掉。
