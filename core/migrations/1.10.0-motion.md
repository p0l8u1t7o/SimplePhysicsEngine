### 標記與規則（core 1.10.0 已實作，細節見 `core/MIGRATION.md`）

- 每個 root 有 `userData.coreModel = meta.id`。**會動的子群組另外標 `userData.coreModelPart = meta.id`**（`rod`、`actuator`、`table`、`carriage`、`spin`、`socket`、`fingers[]`、`plunger`、`inner`）。
- **站保留自己的移動群組**：第 3 節一律寫成「站原本的移動群組留著，把模型的可動子群組 `add` 進去」。這樣關節物件、`userData.on`／`nested` 標記、每格改位置的程式都不用動，全場檢查的關節與剛體和原本完全相同。
  - 背景：全場檢查（`core/verify/scene.mjs`）的「直接相連」放行範圍是「關節的父群組底下的網格」。1.10.0 之前，模型的可動子群組如果直接當關節用，父群組變成模型的 root，放行範圍會縮小（化學桶開蓋站的套筒撥爪與 Z 軸立柱原本重疊 14 mm 靠這條放行，直接用 `nutrunner.socket` 當關節會多出干涉）。
  - 1.10.0 的 `scene.mjs` 會往上跳過 `coreModel` 的 root 再判斷安裝關係，所以「直接用模型的子群組當關節」（例如 `slideTable.table`、`airCylinder.rod` 留在 root 裡由站直接改位置）放行範圍也和原本相同；兩種寫法並存時結果一致（合成場景驗過）。保留站的群組仍是預設寫法，因為要改的程式最少。
- **走線（`cable()`）的線夾固定面**：
  - 模型 root 直接掛在走線的 parent 底下時，root 的直接子網格（本體、底座、導軌）算固定面，和換用前「直接是 parent 的子網格」相同；還留在 root 裡的可動子群組不算。
  - 站把可動子群組改掛到自己的移動群組後（例如 `carriage.add(axis.carriage)`），對那個群組走線（`cable(carriage, …)`）時，子群組裡的網格算固定面。
  - **夾指（`parallelGripper.fingers[]`）與擺動缸（`pivotCylinder.actuator`）已經標 `userData.cableHost = false`**：它們改掛到站的群組後仍然相對那個群組在動（站把它們當關節用），不能當固定面——換用前它們也是站裡的群組，本來就不算。站要把別的可動子群組直接當關節、又掛在走線的 parent 底下時，自己標 `子群組.userData.cableHost = false`。
  - 受影響的走線見第 3 節各站的「走線」欄；換用後一律比對夾具數量與位置。
- 既有的 `gauge`（Ø96＋指針）外觀和兩站的 FRL 壓力表不同，所以 `frl` 的壓力表是自己的圓柱，沒有改用 `gauge`。

## 換用後的比對（四份對照共用）

每一站換用前後用 `core/tools/scene-dump.mjs` 比對場景，再跑檢查與截圖：

```powershell
node core/tools/scene-dump.mjs <專案> --out TEMP/<簡稱>-after.json                                   # 換用後傾印
node core/tools/scene-dump.mjs --diff "TEMP/b2-dump/<專案資料夾名>.json" TEMP/<簡稱>-after.json --ignore-names   # 和換用前比
node core/tools/check.mjs <專案> --quick                                                             # 數字要和換用前相同
node core/tools/shots.mjs <專案> --out TEMP/<簡稱>-shots --compare TEMP/shots-b2-base --port <p>     # 0 張超過門檻
```

- 換用前的傾印已經放在 `TEMP/b2-dump/<專案資料夾名>.json`（core 1.10.0、各站還沒換用第二批時產生；站的程式在那之後被別人改過就要重新產生）。
- 目標是「結論：完全相同」。它比的是每個零件的幾何、頂點、世界矩陣、材質屬性、陰影旗標、可見性、名稱與走線五金，外加燈光與虛擬相機，9 個時間點、所有情境；多一層 root、建立順序不同都不算差異。走線五金（線夾、夾腳）另外有一段統計，夾腳跑掉會列在那裡。
- `--ignore-names`：共用模型會給原本沒有名稱的網格預設名稱，這不算外觀差異；走線五金的名稱照比。
- 它不比的：群組階層與 `userData`（`fx`、`guide`、`on`、keepout…）、貼圖內容、時間點之間的動作——所以 `check.mjs`（干涉、配線、站內自有檢查）與截圖仍然要跑。

## 各站換用後的補充（2026-10-05，四份對照共用）

7 站照這四份換用時發現、上面各節沒寫到的事。之後的站換用時照這裡做。

- **原本是「站的普通群組」的設備換成模型**（相機、讀碼器、天平、進樣器、滴定儀、操作電腦、安全掃描器…）：root 有 `coreModel`，父群組上的 `cable(父群組, …)` 會把它的直接子網格當線夾固定面，換用前不會。線夾落在它 65 mm 內時走線五金會變多或改釘位置，要標 `模型.root.userData.cableHost = false`（酸鹼的分析天平、快門的下視相機），或保留原本那一層站內群組再把模型 root 放進去（快門的滑台）。先照文件換，傾印比對報走線五金不同再標。
- **`airCylinder` 用 `grow`**：桿端群組 `tip` 每格都在動，全場檢查把它算成關節。站原本掛在活塞桿上的零件（推板）改掛到 `tip`，`scene-verification.json` 的 `joints` 才和換用前相同；掛在 `rod` 上每支氣缸會多 1 個關節（軍規的推／拉料氣缸）。
- **`visionCamera` 的 `label`**：載入模型當下沒有 `document` 就不建立（`shapes.js` 的 `decal` 也是）。檢查腳本晚補 `document` 的站，標籤留在站內畫（SSD 的手腕相機）；已登記在 `core/REQUESTS.md`。
- **`visionCamera` 的 `view.name`、閃光燈的旋轉**：虛擬相機預設名稱是 `camera view`，閃光燈掛在 root 底下所以會跟著 root 的旋轉。`scene-dump.mjs --diff` 修正後這兩項都不算差異（燈光只比位置與目標點，`--ignore-names` 涵蓋燈光與相機），站內不用再傳 `name: ''`，也不用把燈轉回世界方向。修正前換用的站留著 `name: ''`，無妨。
- **原本有名稱的網格**：對照的程式片段有些只在註解寫「名稱照舊」。換用後要把名稱指定回去（例如軍規 `camBody.name = 'S1 頂視相機'`、`tcLens.name = 'S1 頂視鏡頭'`），站內用名稱判斷的 allow／verify／keepout 才不會掉。
- **實例批次（腳座、底座螺栓）在有位移的 root 裡**：`scene-dump.mjs --diff` 修正後不再誤報（各實例的世界矩陣照比）。化學桶的 `jibCrane`、回收分揀 `beltConveyor` 的腳座都已經用模型的。
- **`flexFeeder`**：預設 `bodyMaterial` 是 `MAT.black`；站有自己的深色材質時明確傳入，之後改站內材質才不會漏。
- **`codeReader`**：機身網格的預設名稱是 `camera body`（沿用相機的組裝函式），站內規則要用名稱時留意。
- 各節寫的行號是 core 1.10.0 提交時的，站改過後會差幾行，以函式與註解為準。
